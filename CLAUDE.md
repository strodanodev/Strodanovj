# Strodano VJ - project notes for Claude Code

Open-source, lightweight Resolume-style live-visuals (VJ) app. GPL-3.0. Owner: Sedano (strodanodev/Strodanovj).

## Two editions in this repo

- `web/` - **the edition under active development.** Plain HTML + classic scripts, WebGL2, no build step, no dependencies. Open `web/index.html` in Chrome/Edge; edit and refresh. Must keep working from `file://` (so: no ES modules, no fetch of local files, no bundler).
  - `shaders.js` built-in effects/generators (`vec4 fx()` / `vec4 gen()`, params 0..1 in `p`/`q`)
  - `engine.js` GL helpers, shader registry (built-in, custom, single-pass ISF), media pool, composition, renderer, output mapping (slices, homography corner-pin, mesh warp, masks), save/load
  - `mediafolder.js` remembered media folder (File System Access API; handle kept in IndexedDB, Reconnect button when permission lapses). Also remembers files added one by one (`looseFiles`, IndexedDB key `looseFiles`): every file drop handler calls `rememberDropped(e.dataTransfer)` synchronously, and Add media / Add tracks / Add songs go through `pickFiles` (showOpenFilePicker; the hidden `<input type=file>` is only the fallback). On start `initMediaFolder` reloads them (relinking "missing file" clips and refilling the track list / playlist); lapsed permission shows Reconnect on the Files tab, which asks for the folder and each file in one click
  - `midi.js` Web MIDI + learn mode. Mappable controls carry `data-midi="<target id>"` (`master`, `crossfade`, `tap`, `resync`, `column:C`, `clip:L:C`, `layer:L:opacity|bypass|solo|eject`, `fx:<uid>:<param>|mix|bypass`, `gen:<uid>:<param>`); effects and generator clips carry a `uid` saved in the .svj so mappings follow them; mappings live in localStorage, app-wide
  - `keys.js` keyboard shortcuts on `KeyboardEvent.code`, capture phase; ignored while typing, in the Shader Editor, or with Ctrl/Cmd/Alt
  - `motion.js` beat-synced LFOs (`owner.mod[paramIndex] = {shape, rate, depth}` on effects and generator clips, applied at render time by `modParams`, so the saved slider value stays the centre) and the beat lengths for clip transitions. Transitions themselves are in `engine.js` (`switchActive` / `applyTransition`: the outgoing clip keeps playing and fades out over `L.trans` beats into `L.tf`; `L.transType` picks one of `TRANSITION_TYPES` in `transProg`: fade, 4 wipes, dissolve, luma, through black, zoom, iris)
  - Extra clip types register in `CLIP_TYPES[type] = {toJSON, fromJSON, free, props}` (engine.js) and draw themselves via `c.draw(fbo, layer)`; `SOURCE_PANELS` adds their entries to the Sources tab (drag payload `{kind: 'make', make()}`):
    - `camera.js` camera clips (shared `getUserMedia` stream per device) and the camera *input*: one camera analysed on a 64x36 copy every other frame into `camFeat` {motion, x, y, bright}; shaders get `uniform vec4 cam` and `camTex` (unit 3); modulator sources `cmotion|camx|camy|clight`; six "(cam)" effects. Mirror flips `camFeat.x` only
    - `text.js` text clips: one line per cue (N key / beat advance); the line is rasterised once (fill in R, outline in G) and only redrawn when the shown words change; size / position / colour / animations are uniforms in `textProg`, so params work with `mod` and MIDI (`gen:<uid>:k`, `findGenClip` matches any clip with `params`)
    - `smart3d.js` three.js scenes (`SCENES3D`), rendered by a `WebGLRenderer` that shares the engine's context into a 4x MSAA target, then copied with `srcProg`. Always `renderer.resetState()` before and after a three.js render. `warm3d` builds the scene and `compileAsync`s it when the clip is created, so a first trigger does not stall on shader compile
  - `vendor/three.min.js` a three.js r186 subset as a classic script (global `THREE`), built from `tools/three-entry.js` with esbuild; add a class there and rebuild when smart3d.js needs one. `demoComp` places 4 different random `SCENES3D` in new projects (one starts on layer 2)
  - `hands.js` hand tracking: MediaPipe GestureRecognizer (Apache-2.0) **in a Blob worker, never on the render thread** (on the main thread it froze the app; in the worker ~27 ms per analysis on the GPU delegate at 640 px, 240-400 ms on CPU). Loaded only on "Track hands". `vendor/mediapipe/*.gz.js` hold the wasm, the model and MediaPipe's JS gzipped + base64 (`tools/pack-b64.mjs`), unpacked with DecompressionStream; the worker's source is the bundle text + `HAND_WORKER`, the loader and wasm are Blob URLs. Frames go over as 640-wide ImageBitmaps (medium-quality resize), one in flight, sent as soon as the worker is free and a new camera frame exists (no rate cap: MediaPipe tracks between analyses, so a low rate is what makes it lose hands; first version capped at 15/s with 320 px and was "slow to detect, hard to re-detect"). Confidence thresholds come from the Sensitivity slider (`handConf`, default ~0.36, live via `setOptions`). A single empty analysis keeps the last hand; a gesture counts after 2 analyses in a row. `handFeat` {present, x, y, pinch, open, size, spread, hands, gesture}; gestures fire `onInputEvent('gest', 0, name, 1/0)`. The Hands panel shows looks per second, ms per look, delegate and confidence
  - `inputs.js` the input chip on every modulatable slider and its picker (Beat / Music / Camera / Hands sources with live levels, Detect = pick the source that moved most in 3 s after a 0.4 s settle, Follow / Push up, Invert, Amount, MIDI knob learn). `lfoControls` in motion.js now just returns the chip. Buttons (clips, bypass...) are mapped in Map mode (the MIDI button) to MIDI notes/CCs *or* hand gestures: midi.js `onInputEvent(type, ch, n, val)` is the one path for both
  - `safety.js` blackout (`outGain()` multiplies the master in renderComp; Shift+B, BLACK button, MIDI target `blackout`); GPU loss: `webglcontextlost` saves (autosave + sessionStorage active clips / outputs / blackout), sets `window.vjKeepOutputs` so engine.js leaves output windows open, and reloads; on `load` it re-triggers the clips and re-attaches the outputs via `openOutput` (works in the desktop app; a browser's pop-up blocker may refuse). More than 3 losses in a minute stop the reloading. Screen wake lock in the browser; confirm-close while an output is live
  - `clipopts.js` video clip in / out (`c.inP` / `c.outP` fractions), `c.loopMode` loop | hold | eject, `c.syncBeats` beat sync (rate = length / beats at `comp.bpm`, phase from the trigger beat `c.sync0`, drift pulled in by nudging playbackRate, seek only past ~0.25 s). Hooks: `clipTriggered` / `clipStart` in engine.js trigger(), `clipOptsJSON` / `clipOptsFrom` / `clipOptsCopy` in save, load and relink
  - `snapshots.js` 8 slots of score.js looks (`captureLook` / `recallLook` / `lookFromJSON`, glide = `score.morph`), F1-F8, MIDI `snap:N`, "on next bar". `vjTick(dt)` (safety + clip options + snapshots) runs in ui.js frame() after update()
  - engine.js `videoFrameNew`: a video is re-uploaded only when it has a new frame (requestVideoFrameCallback; when those callbacks go quiet because the control window is not being drawn, a change of currentTime counts instead, or the output would freeze)
  - `analysis.js` track analysis (`analyseTrack`: BPM, beat grid `grid0` + `beatLen`, first beat of the bar, waveform peaks). Self-contained, because its source is also run in a Worker made from a Blob URL (the only worker that loads from `file://`)
  - `audio.js` DJ audio: two decks on decoded buffers (sample-locked sync; tempo changes pitch, no key lock), the music clock (`musicClock`, which sets `comp.beats` / `comp.bpm` from the audible deck's position while a track plays), live levels in `audioFeat` (shader uniforms `audio.xyzw` = bass, mid, high, level, and `kick`; plus `bar`, `phrase`). The AudioContext is created on first Load/Play, never at page load
  - `analysis.js` also returns `key` / `camelot`, `loudDb` (auto-gain), `flux` (energy) and `mixIn` / `mixOut` / `beatEnd` (seconds: first beat, start of the outro on an 8-bar phrase, last beat)
  - `crate.js` DJ track list: analyses each track once and caches it in IndexedDB `strodano-vj-tracks` by name + size + date (bump `ANALYSIS_VERSION` when `analyseTrack`'s output changes); energy 1..10 relative to the list; next-track suggestions by tempo gap, Camelot key and energy. Audio files in the media folder join the list
  - `mix.js` auto-mix (Mix button: blend, bass swap, echo out, cut; starts on the next phrase or bar, timed in the outgoing deck's beats from `deckPos`, drives `comp.crossfade`), autopilot, and beat-quantised clip launches (`quantHold`, called at the top of `trigger()` in engine.js; a held trigger fires later through `trigger()` again). Runs from `audioTick()`, plus a timer when no window gives frames
  - `analysis.js` sections: `info.sections` = [{type: intro|build|drop|breakdown|outro, bar, bars, t, end}] (bars from `grid0`). Drops are 4-bar blocks with both a beat-locked kick and a level floor between hits; builds are the rising kick-less bars before a drop
  - `score.js` follows the sections at the HEARD position of `audio.clockDeck`: emits them on the music event bus (`emitMusic`, live.js) as 'drop' / 'breakdown' / 'section' with {source:'deck', deck, section, bars}; `sectionNow` / `sectionAhead` / `dropAhead`; `musicFeat.build` / `.drop` for modulation; section looks (auto-score, `score.looks[type]`, saved in the composition as `score`). While `scoreActive()` the Agent (agent.js) leaves clip and look switching alone
  - `segments.js` per-track segment edits (`seg.edits[name|round(duration)]` = [{type, bar, bars, lookMode, look}], saved in the composition's `score.segments`) and the segment editor. Always read sections through `sectionsFor(info, file)` / `segmentsOf(deck)`, never `info.sections` directly, so hand edits win everywhere. `lookMode`: 'type' (default) | a LOOK_SLOTS name | 'own' (`.look`) | 'keep'; score.js recalls `lookForSegment(seg)` at each section change
  - `motion.js` modulators: `mod[k].src` = kick | bass | mid | high | level (audioFeat) | build | drop (musicFeat) pushes the value up from the slider by `depth`; no `src` = beat LFO; `mix` / `midmix` (musicFeat, written by mix.js) follow an auto-mix's progress. The `mix` look slot (score.js LOOK_SLOTS) is recalled when an auto-mix starts
  - `cues.js` track scores: `cues.scores[trackId]` = [{b, id, v?}], b in the track's own beats, id a midi.js control id (anything MIDI-mappable is recordable; playback goes through `midiTarget`). Recorded from DOM `input` / `click` on `[data-midi]` and from `onMidiMessage`; DJ ids (deck:, agent:, crossfade, tap, resync) are never recorded. Overdub replaces a fader's moves only over the stretch touched. trackId = file name + rounded length. Saved inside the composition's `score` block
  - `follow.js` external gear: MIDI clock (`midiClockMsg` from midi.js; least-squares fit over 4 beats of ticks; the first tick after Start or Song Position is that beat) feeds `musicClock` after the decks and before the live listener. Track recognition from the line-in: per-beat log level + bass share from live.js's ring buffer vs `info.rms` / `info.lows` of every analysed track, plus `info.chroma` vs `live.chL` (±1 semitone). Locks only on one clear track AND one clear position found twice; carries the match across live.js beat re-counts. `extDeck()` is the recognised track as a stand-in deck (cueDeck, score.js)
  - `dj.js` DJ panel (decks, waveforms, beat grid, mixer row, section looks row, track list). Built once and refreshed in place from `tickDJ()`, not through the dirty-flag rebuilds. MIDI targets `deck:A|B:play|cue|sync|volume|tempo|bass|load`, `deck:mix:go|auto`, `deck:look:<section>|auto`
  - `live.js` listening: microphone / line-in and long music files (played from a `<video>` element, never decoded whole), a live beat tracker (AudioWorklet onset tap from a Blob URL -> autocorrelation + fold every 0.5 s, phase slew, downbeat vote), and the music event bus `onMusic(fn)` / `emitMusic(type, data)`: song, drop, breakdown, band (calm/groove/peak), phrase, tempo, ended. `musicClock` (audio.js) falls back to `liveClock()` when no deck plays. Breakdown = bass gone for 2 bars; drop = the next kick with the bass back; song change = silence gap, lasting tempo change, or harmonic novelty (chroma from a 16k-point analyser), never near a breakdown. Analysed deck sections (score.js) override the live drop/breakdown guesses
  - `agent.js` the Agent: plays the USER'S composition - it has no layers of its own (decided 2026-11-17: the owner wants it to operate the project the user set up). Unit of change is a scene `{band, drop, col, show: {layerIndex: column}}`: `makeScene` plays a column tagged for the band as built (`comp.agentTags` Calm / Groove / Peak / Drop, saved with the composition), else combines untagged clips itself with energy as layer count (calm: bottom layer only, groove ~2/3, peak all); `varyScene` changes one clip or swaps one upper layer. `applyScene` triggers clips (`agentTrigger`, skips the quantise) and fades layers between 0 and the user's own level (`agent.base` per layer object, taken when first touched; moving a fader sets a new level; layers faded out are ejected; `agentLevel(L)` is what compToJSON saves; `agentRelease` / Stop restores levels). Never touches locked or bypassed layers; layer transitions and effects are the user's. Timing: new scene on song change (8 beats), drop scene cut in on a drop, calm in breakdowns / intros / outros (16 beats), variation every `agent.vary` bars counted on `comp.beats` in `agentTick` (works with no music), all on the next bar; the last two beats before an analysed drop dim the layers (`agent.dim`). `agentClockSync()` runs first at every entry point and shifts all beat stamps when the clock jumps (song start, mix end, Resync), exactly once. A clip you trigger brings that layer up and makes the Agent wait 8 bars. Steps aside (and releases the layers) while `scoreActive()`. `agentStarter()` fills an empty grid with tagged generator columns. Do not name a top-level function `schedule` (ui.js owns it)
  - `record.js` recording: composition output copied into a canvas (30 fps) + the final mix (`audio.out`, plus the mic) to MediaRecorder, MP4 (H.264/AAC) when supported else WebM, written to disk chunk by chunk via showSaveFilePicker (in memory otherwise), stops at one hour. Auto render = play a music file from the start (or the track list with autopilot) with the Agent on, recording until the end. Real time only; while recording `audio.recording` drops the output-latency shift so picture and sound line up in the file
  - `agentui.js` Agent panel, newcomer-first: Start/Stop (`startShow`: Agent on + autopilot in playlist order, `mixer.order`), Vibe (`AGENT_VIBES` chill/club/festival in agent.js: sets `agent.vary`, mix style/bars and `vibeBand` shift), Next song, Record, plus New scene / Hold / Drop!, and "Add starter clips" when no layer has anything to play. Everything else (listen source, vary rate, column energy tags, render) is under "More options". Refreshed in place from `tickAgentUI()`. MIDI targets `agent:on` (= Start/Stop) `|next|hold|drop|rec`
  - `playlist.js` the Agent playlist, shown instead of the clip grid while the Agent panel is open (Playlist / Layers tabs). The playlist IS `crate.tracks` in order (drag to reorder, drop files where they should go); order and per-song settings persist in localStorage `strodano-vj-playlist`. Per song: waveform, IN/OUT transition markers (`t.inAt` / `t.outAt`, snapped to bars; `inPoint` / `outPoint` in crate.js are what mix.js and dj.js use), junction `t.jStyle` (audio mix style) / `t.jVis` (visual hand-off: with the mix / quick / cut + flash, applied by `agentMixStart` when the auto-mix starts), and `t.plan` = one Agent scene of the user's clips per analysed section (`plannedScene()` is preferred by `change()` except for vary / next, checked by `validScene`; click a chip to reroll). Plans are rebuilt when `compSig()` (clips, locks, bypass, tags) changes; their clips' shaders are compiled ahead (`warmScene`, one per frame, playing/next song first)
  - Layer lock: `L.locked` (saved) - the Agent (column launches, user-play detection), `recallLook` (score.js) and track-score cues (cues.js `cueLocked`) leave the layer alone. Lock buttons on grid layer rows and as chips in the playlist header (shown in both Playlist and Layers views)
  - `panels.js` main-column panels (DJ decks, Agent, More options, Playlist, Composition grid): a slim title bar (click = minimise, ↺ = automatic size; the playlist's minimise button is in its own header) and a drag handle under each. More options is moved out of #agent to be its own panel. A user size is flex `0 0.02 <px>` so other panels give way first; the bottom row keeps `min(240px,34vh)`. Saved in localStorage `strodano-vj-panels`; panelSync follows the DJ / Agent / view toggles through a MutationObserver
  - `ui.js` DOM UI, Advanced Output editor, Shader Editor, autosave (localStorage), main loop (exactly one rAF request outstanding; the watchdog must never add a second)
- `desktop/` the Electron app (Electron 44, electron-builder 26): loads `../web` (packaged as resources/web), no background throttling, display kept awake, quit confirmation, no reload accelerator, output windows allowed by `setWindowOpenHandler`, permissions for camera / MIDI / file system. `npm run selftest` boots it, opens an output window, simulates a GPU reset and prints `SELFTEST {json}` (exit 0 = pass; `STRODANO_SOFTWARE_GL=1` for machines without a GPU). macOS builds are signed ad hoc in `afterpack.js`. `.github/workflows/desktop.yml` builds Windows (nsis x64) and macOS (dmg arm64 + x64) and, on a `v*` tag, a **draft** release; build.yml (native C++) no longer releases
- Native C++ (`src/`, `CMakeLists.txt`) - OpenGL 4.1 + FFmpeg + Dear ImGui + FFGL 2.x plugin host. Kept as the later native/FFGL edition. `.github/workflows/build.yml` builds the Windows NSIS installer and macOS .dmg; first run (2026-11-17) was green on Linux, Windows and both macOS architectures.

## Decisions already made

- Web first, because the owner wants to test without installing/compiling and change code live. FFGL plugins are dropped in the web edition; ISF/GLSL shaders replace them.
- Same workflow and panel arrangement as Resolume (layer/column clip grid, faders, B/S/X, A/B crossfader, BPM tap, effects, advanced output) but its own visual design, not a pixel copy.
- v1 scope: core VJ features + advanced mapping (multiple screens/slices, warping, masks). Since added: media folder, MIDI learn (including effect and generator parameters), keyboard shortcuts, beat LFOs on parameters, beat-timed clip transitions (10 types), music and camera sources for sliders, camera clips and camera input with "(cam)" smart effects, text clips, three.js 3D generators (10), hand tracking and gestures, one input picker for every slider, camera on a layer in one click. Not yet: OSC, per-clip effects, body pose / face tracking.
- Hard requirement: steady 30 fps or better with H.264 MP4 / .mov clips.

## State of testing

- Web: measured on a real GPU (RTX 3080 Ti, 2026-11-17): 3 x 1080p video layers with effects composite in ~1.3 ms, a 1080p output window costs ~1.5 ms (4K ~4.1 ms), so the `drawImage` copy path is not a bottleneck. Media folder tested with an OPFS folder, MIDI with synthetic messages. **Still never used by hand** (drag from Explorer, real pop-up output on a second display, a real MIDI controller, the real folder picker).
- Native: CI builds Linux (`--selftest`), Windows installer and macOS arm64/x86_64 .dmg. Installers never run by hand.
