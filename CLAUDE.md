# Strodano VJ - project notes for Claude Code

Open-source, lightweight Resolume-style live-visuals (VJ) app. GPL-3.0. Owner: Sedano (strodanodev/Strodanovj).

**Open core (since 0.4.0):** this public repo is the Free app. The Pro and Festival features (DJ mode: decks UI, track
analysis, track list, auto-mix, sections and section looks, segments, track scores, track recognition; Agent Mode and
its playlist; recording; rekordbox import) are closed source in the private repo `strodanodev/strodano-vj-premium`
(checked out beside this one as `../strodano-vj-premium`, with its own CLAUDE.md for their internals). `tools/pro.mjs`
joins them into one classic script (minified with esbuild, a desktop devDependency: `npm ci` in desktop/ first; top-level
names are kept, which the core relies on) that sets `window.SVJ_PRO`. **Since 0.4.1 no release contains it**: `web/prodl.js`
(core, loaded where the bundle used to be, right after `looks.js`) puts the stored bundle into the page synchronously at
start-up, and downloads it once the app is signed in to a paid plan (`proFetch`, on `entReady` and every `strodano-plan`):
the premium pack's signed link from `GET /api/app/pack`, then `vj.strodano.live/premium/pro-api<PRO_API>.json` = {manifest,
sig} and the file it names. The manifest {v, api, version, file, sha256, size} is signed with `MODULE_SIGNING_KEY` (ECDSA
P-256, private half in website/.env.local only: back it up; public half `PRO_PUBKEY` in web/prodl.js AND desktop/pro.js).
Desktop: `desktop/pro.js` keeps it in userData/pro and hands it over with `sendSync('pro:load')` only after checking the
signature, SHA-256 and size, so a changed copy never runs. Browser / phone: localStorage `strodano-vj-pro`, checked right
after it runs; a bad copy is deleted and the page reloads. A first download reloads the page when no show is live
(`proShowLive`), else waits for the next start. `tools/build-mobile.mjs` builds, signs and publishes it behind the
`/premium/` middleware (fails without the private repo or the key; checks PRO_API in prodl.js, desktop/pro.js and the
private pro.json agree). Development loads `web/pro/pro.js` directly (`npm start` = unpackaged, or a localhost page;
localStorage `strodano-vj-pro-test` = 'download' plus `strodano-vj-pack` exercise the released path), so run
`node tools/pro.mjs --watch` (unminified) while working; CI's selftest runs unpackaged with it. The packaged selftest
reports `pro` ('' until an account downloaded it). Without the bundle every Free feature works: core code reaches Pro only
through `typeof X === 'function'` guards (never `typeof agent`: index.html has an element `id="agent"`, a global),
`proGate` / `proLoaded` / `agentOn` (plan.js), and saved Pro data passes through untouched (`proKept` / `scoreSave` /
`scoreLoad` in engine.js, `wsKeptPlaylist` in workspace.js). Tested 2026-11-20: signed / tampered / other-API bundles
against desktop/pro.js; in the browser a stubbed paid account downloading, the automatic restart into Pro, a tampered
copy removed, the phone page with the stored bundle; the packaged Windows app with no bundle, a genuine one (pro 0.4.0)
and a changed one (refused). Not tested: a real paid account against the live site end to end, macOS.
Never move Free behaviour into the private repo, and never describe Pro internals here.

## Two editions in this repo

- `web/` - **the edition under active development.** Plain HTML + classic scripts, WebGL2, no build step, no dependencies. Open `web/index.html` in Chrome/Edge; edit and refresh. Must keep working from `file://` (so: no ES modules, no fetch of local files, no bundler).
  - `shaders.js` built-in effects/generators (`vec4 fx()` / `vec4 gen()`, params 0..1 in `p`/`q`)
  - `engine.js` GL helpers, shader registry (built-in, custom, single-pass ISF), media pool, composition, renderer, output mapping (slices, homography corner-pin, mesh warp, masks), save/load
  - `mediafolder.js` remembered media folder (File System Access API; handle kept in IndexedDB, Reconnect button when permission lapses). Also remembers files added one by one (`looseFiles`, IndexedDB key `looseFiles`): every file drop handler calls `rememberDropped(e.dataTransfer)` synchronously, and Add media / Add tracks / Add songs go through `pickFiles` (showOpenFilePicker; the hidden `<input type=file>` is only the fallback). On start `initMediaFolder` reloads them (relinking "missing file" clips and refilling the track list / playlist); lapsed permission shows Reconnect on the Files tab, which asks for the folder and each file in one click
  - `midi.js` Web MIDI + learn mode, and MIDI clock in (`midiClockMsg`, least-squares fit over 4 beats of ticks; `midiClock()` feeds `musicClock` after the decks and before the live listener; Free). Mappable controls carry `data-midi="<target id>"` (`master`, `crossfade`, `tap`, `resync`, `column:C`, `clip:L:C`, `layer:L:opacity|bypass|solo|eject`, `fx:<uid>:<param>|mix|bypass`, `gen:<uid>:<param>`, nudge / speed trim `layer:L:<k>` and `clip:L:C:<k>` with k = `nudge+|nudge-` (held) | `nudge` (bipolar) | `speed+|speed-|speed1`). Target shapes: `{set(v, src)}`, `{fire()}`, `{hold(down, src)}` (momentary: `onInputEvent` calls it on press AND release), and a bipolar target adds `bend(a)` with a in -1..1 (for gamepad sticks; a note or gesture on it pushes +1 while held); effects and generator clips carry a `uid` saved in the .svj so mappings follow them; mappings live in localStorage, app-wide. Controllers (Phase 1 of ../controller-mapping-spec.md, 2026-11-20): input keys are `<dev>|<type>:<ch>:<n>` (dev = profile id, `midi:<port name>`, or `*` = any device: gestures and pre-2026-11-20 mappings, migrated from `strodano-vj-midi` which is read once and never written; now stored in `strodano-vj-controllers` {format 1, map, kinds, pickup, profiles}); `ctlLookup` = own mapping > profile default > `*`; a map value `''` switches a profile default off; `bindMidi` replaces only the same device's (and `*` same-family) binding, so several inputs can drive one target; kinds knob | fader (pickup via `get()`, `PICK_TOL` 0.03, on by default) | encoder (relative two's complement, `ENC_STEP` 1%) | pad; profiles `registerProfile({id, name, match: {midiPort}, init, controls, defaults, leds(dev)})` matched on the port name (Windows "2- " prefix stripped), `init` sent on connect (SysEx asked for only when a profile needs it), `ctlTick` (from `vjTick`) diff-sends `leds()` every 30 ms; Controllers panel (Composition tab): devices, mappings by device with kind, Pickup, Export / Import (strodano-controllers.json), Clear all. Tested 2026-11-20 with synthetic messages and a stand-in profile + output in the browser; not with real hardware
  - `apc40.js` (desktop page only, after midi.js) the AKAI APC40 mkII profile (Phase 2 of ../controller-mapping-spec.md, 2026-11-20): Ableton Live mode SysEx on connect; track strip = layer, 5 pad rows = columns of the 8x5 window `ctlWin` (bank arrows move it); device knobs = `focus:0..7` (midi.js `focusNow`: what the properties panel shows; Device </> = clip params then effects, Bank </> = pages of 8), `sync` (the ring value we send is the knob's position, so no pickup); Shift (note 98) layer: top pads = snapshots, track 1 Activator = blackout; `leds()` = pad colours (layer hue dim = loaded, green = playing, pulsing = pendingCol, white = selected), track buttons, scene LEDs, knob rings. Generic in midi.js: virtual targets `grid:X:Y`, `track:X:<k>`, `scene:Y`, `selected:<k>`, `win:<dir>`, `focus:<k>|prev|next|page-|page+|bypass`, `stopall`, `bpm` (step), `layer:L:select`; a target may carry `rid` (the real id, for reflectMidi / cueRecord); profile `alias(k)`, `shift`, `shiftDefaults`, `grid {w,h}`; LED list items `[key, value, channel override]`; `ctlOutline` draws `#ctlWinBox` in #grid and `.ctl-focus` on the focused effect card + its 8 sliders (`--ctl-focus`). Message numbers from AKAI's mkII protocol, **never checked on a real unit**
  - `gamepad.js` (desktop page, after apc40.js; Phase 3 of ../controller-mapping-spec.md, 2026-11-20): `gpTick(dt)` from `vjTick` polls `navigator.getGamepads()` (standard layout only); all pads are ONE device `gamepad` (profile `GP_PROFILE`, `match: {gamepad: true}`); buttons -> `onInputEvent('btn', 0, n, 0|1, 'gamepad')` (LB = Shift `btn:0:4`, View = `overlayKey` `btn:0:8`; L3 blackout needs `holdMs` 500; LT/RT `analog` on a bend target = clip nudge by pressure, `sign` -1/+1); sticks handled in `gpStick` every frame: dead zone 0.15, Y inverted, mode per key in `midi.stick` ('nudge' default: full sweep 1.5 s; 'spring': rest + 0.5 x push, back on release), bend / hold / step (BPM) / fire targets too; learnt in Map mode by a push past 0.6. Defaults: D-pad = `sel:layer+|layer-|col-|col+`, A `sel:trigger`, B `selected:eject`, X `sel:column`, Y `selected:bypass`, RB tap (Shift: resync), Menu `agent:on`, R3 `focus:reset`, left stick crossfade / master, right stick `focus:0` / `focus:1`, Shift + A/B/X/Y/D-pad = snapshots 1-8. `gpGone` releases held inputs on disconnect. Panel rows `gpPanelRows` (Nudge / Spring per stick). Overlay (midi.js `ctlOverlay`, `#ctlOverlay`): profile `overlay(dev, shift)` rows `[name, target id, text]`, `overlayKey` or `overlayOnShift` (APC: after 0.4 s). Tested with a stand-in `navigator.getGamepads` in the browser; **not with a real pad, the Electron app or the ROG Ally**
  - `ctlwizard.js` (desktop page, after gamepad.js; Phase 4 of ../controller-mapping-spec.md, 2026-11-20): `ctlWizard(dev)` = guided setup for a MIDI device without a profile (Controllers panel: Set up... / Set up again / delete user profile). While open, `midi.capture = {dev, fn}` takes that device's input before anything else in `onInputEvent`. Steps faders (CC range >= 64) / knobs (> 6 distinct values = knob, else encoder; style twos | sign | offset from the values seen, `wzKnobKind`) / pads (note on, or CC only 0/127) / name + pads per row. Saves `midi.userProfiles` entry `{id: 'user:<slug>', source: 'user', match: {midiPort: '^<escaped port name>$'}, controls (kind, enc), defaults (faders track:N:opacity, last = master when > 8; knobs focus:0-7; pads grid:X:Y), grid}`, then `ctlMoveKeys(old dev, new id)` (also used when a profile is deleted, back to `midi:<name>`) and `midiHook()` re-matches. midi.js: `ENC_STYLES` / `encDelta(r, style)`, control `enc`, profile `grid` validated (1..16). Tested with a stand-in MIDI port in the browser; not with real hardware
  - Controller sync (Phase 5, 2026-11-20, in midi.js, both pages): one document per account on the website (`GET /api/app/controllers`, `POST /api/app/controllers/save {data, baseAt}`; table `controller_settings`; 64 KB; every plan). `ctlSync` {at = server updatedAt last seen, dirty} in localStorage `strodano-vj-ctlsync`; `saveMidiMap()` marks dirty and pushes 5 s later (`saveMidiMap(true)` = came from the account, no push); pull after `entReady`, on `strodano-plan` and `online`; 409 = another device saved: `ctlTakeRemote(data, at, merge)` puts the account's copy in and this app's on top (deletions made offline come back), then pushes again; the replaced local copy goes to `strodano-vj-controllers-backup`. Tested against the real website handler with an in-memory db stand-in; **the SQL and the deployed site are not tested**
  - `ctlmap.js` (desktop page, after ctlwizard.js; 2026-11-20, after the ROG Ally test): the **Controllers tab of the Shortcuts popup** (keysModal; keys.js `toggleKeysHelp(show, tab)` / `keysTab` 'keys' | 'ctl', `drawKeysTabs`, modal class `wide`). Control first: device buttons, then every control of the device (`ctlMapControls`: gamepad buttons + sticks, profile `controls` / `defaults` with names from profile `label(k)` (apc40.js), keys mapped by hand), each with an action list (`ctlActionGroups`, Default / Nothing / groups), kind (CC) or Nudge / Spring (sticks), **Pick on screen** (`midi.pick` = {key, name}: closes the popup, the next click on a `[data-midi]` control maps it, then the tab reopens; Esc cancels) and Reset. Clip pads and the Shift layer are in collapsed groups. Pressing a control lights its row (`ctlMapSeen(dev, k)`, called by onInputEvent and gpStick). The Composition tab's Controllers section now links here (Edit mappings...); the phone page keeps the old per-device list
  - Full screen (2026-11-20): sidebar `#fsBtn` (data-act fullscreen), keys.js `appFullscreen(on)` (desktop bridge `strodanoDesktop.fullscreen` get / set / onChange, else the page's Fullscreen API), MIDI / gamepad target `fullscreen` (gamepad Shift + Menu). desktop/main.js: the control window hides its menu bar (File / Edit / View / Help) while full screen, remembers it in `userData/window.json` and reopens full screen, and maximises when the work area is smaller than 1600 x 1000 (a handheld at 150 %). Selftest passes; full screen itself not tried on the Ally
  - `keys.js` keyboard shortcuts on `KeyboardEvent.code`, capture phase; ignored while typing, in the Shader Editor, or with Ctrl/Cmd/Alt
  - `motion.js` beat-synced LFOs (`owner.mod[paramIndex] = {shape, rate, depth}` on effects and generator clips, applied at render time by `modParams`, so the saved slider value stays the centre) and the beat lengths for clip transitions. Transitions themselves are in `engine.js` (`switchActive` / `applyTransition`: the outgoing clip keeps playing and fades out over `L.trans` beats into `L.tf`; `L.transType` picks one of `TRANSITION_TYPES` in `transProg`: fade, 4 wipes, dissolve, luma, through black, zoom, iris)
  - Extra clip types register in `CLIP_TYPES[type] = {toJSON, fromJSON, free, props}` (engine.js) and draw themselves via `c.draw(fbo, layer)`; `SOURCE_PANELS` adds their entries to the Sources tab (drag payload `{kind: 'make', make()}`):
    - `camera.js` camera clips (shared `getUserMedia` stream per device) and the camera *input*: one camera analysed on a 64x36 copy every other frame into `camFeat` {motion, x, y, bright}; shaders get `uniform vec4 cam` and `camTex` (unit 3); modulator sources `cmotion|camx|camy|clight`; six "(cam)" effects. Mirror flips `camFeat.x` only
    - `text.js` text clips: one line per cue (N key / beat advance); the line is rasterised once (fill in R, outline in G) and only redrawn when the shown words change; size / position / colour / animations are uniforms in `textProg`, so params work with `mod` and MIDI (`gen:<uid>:k`, `findGenClip` matches any clip with `params`)
    - `smart3d.js` three.js scenes (`SCENES3D`), rendered by a `WebGLRenderer` that shares the engine's context into a 4x MSAA target, then copied with `srcProg`. Always `renderer.resetState()` before and after a three.js render. `warm3d` builds the scene and `compileAsync`s it when the clip is created, so a first trigger does not stall on shader compile. `morph` (Particle Morph) is the GPU particle scene: every shape is a prebuilt vertex attribute and a morph only swaps which two are `position` / `aTo` (period = `comp.beats` / Morph every), all motion in its vertex shader; 100k points, 40k on `VJ_MOBILE`. `picture` (Picture Particles, `sources: true`) samples another texture in its vertex shader: the layer below's `outTex` (layers render bottom first, so it is this frame's) or `camState.tex`, chosen by `c.src` ('camera' or absent = below, saved). The engine texture goes to three.js as a duck-typed external texture `{isExternalTexture, sourceTexture}` (three binds it, never uploads; ExternalTexture itself is not in the vendored subset). Scenes' `update(p, dt, L, c)` get the layer and clip (L is null for thumbnails). GPU point scenes share `pointsMat(uniforms, decl, body, frag)` (soft round points sized by distance, additive; the GLSL body sets `p` / `sz` / `vCol`, alpha 0 hides a point; helpers hash / hsl / flow; built-in hand pull `uPull`), `ptMesh` (frustumCulled off) and `ptFrame(mat, camera, handPull)` once per frame: fireworks (16 burst slots in a `vec4 uBurst[16]` uniform array, flight is a function of age), vortex and embers (stateless, driven by accumulated time uniforms), bokeh ('disc' fragment), attractor (CPU Euler integration, re-centred / re-scaled from the cloud's mean and RMS every frame, runaways respawn). Since 2026-11-18 the older Particle Storm, Star Warp and Hand Comet are on `pointsMat` too (same params, so saved clips and MIDI keep working): storm adds a flow drift and a kick ripple, stars fly in the shader (`uTravel`, 4 points per star stretch into streaks with speed), comet writes only newborn particles (birth place / velocity / time) and ages them in the shader. Also 2026-11-18: supernova (charge from `musicFeat.build`, bang when `musicFeat.drop` starts; while `songSections()` (the clock deck plays a track with analysed sections) it rests outside builds, else an N-bar cycle; hand: fist / open; shader gets charge, charge at the bang and time since it), terrain (`vec4 uHist[96]` uniform of bass/mid/high/kick rows shifted at the row rate, `uFrac` scrolls between shifts; idle hills when silent), shatter (`sources: ['below','camera','text']`, `ownText: true`: `c.text` drawn to a 2D canvas and uploaded into its own GL texture, freed via `inst.dispose()` which `CLIP_TYPES['3d'].free` calls; grid cells are rigid shards), harmono (two ratio sets morphed in the shader, pen sweep per bar). Scene option `sources` is a list of `SRC3D_LABELS` keys; `c.src` absent = 'below'. Trails (2026-11-18): `c.trail` 0..1 on every 3D clip (slider after the scene's own, MIDI `gen:<uid>:trail`, saved as `trail`; new clips take the scene's `trail` default, loaded clips without one get 0). `trail3d` keeps a per-clip `mkRT` pair (`c.tr3`, made on first use, freed at 0 and in `free`), `trailProg` = max(prev * fade - 1.5/255, current), fade = exp(-dt / (0.04 + k^2 * 3)) so it is frame-rate independent; cleared when the clip was not drawn for 0.25 s (re-trigger). Not modulatable by LFO / music yet (not in `params`)
  - `vendor/three.min.js` a three.js r186 subset as a classic script (global `THREE`), built from `tools/three-entry.js` with esbuild; add a class there and rebuild when smart3d.js needs one. `demoComp` places 4 different random `SCENES3D` in new projects (one starts on layer 2)
  - `hands.js` hand tracking: MediaPipe GestureRecognizer (Apache-2.0) **in a Blob worker, never on the render thread** (on the main thread it froze the app; in the worker ~27 ms per analysis on the GPU delegate at 640 px, 240-400 ms on CPU). Loaded only on "Track hands". `vendor/mediapipe/*.gz.js` hold the wasm, the model and MediaPipe's JS gzipped + base64 (`tools/pack-b64.mjs`), unpacked with DecompressionStream; the worker's source is the bundle text + `HAND_WORKER`, the loader and wasm are Blob URLs. Frames go over as 640-wide ImageBitmaps (medium-quality resize), one in flight, sent as soon as the worker is free and a new camera frame exists (no rate cap: MediaPipe tracks between analyses, so a low rate is what makes it lose hands; first version capped at 15/s with 320 px and was "slow to detect, hard to re-detect"). Confidence thresholds come from the Sensitivity slider (`handConf`, default ~0.36, live via `setOptions`). A single empty analysis keeps the last hand; a gesture counts after 2 analyses in a row. `handFeat` {present, x, y, pinch, open, size, spread, hands, gesture}; gestures fire `onInputEvent('gest', 0, name, 1/0)`. The Hands panel shows looks per second, ms per look, delegate and confidence
  - `inputs.js` the input chip on every modulatable slider and its picker (Beat / Music / Camera / Hands sources with live levels, Detect = pick the source that moved most in 3 s after a 0.4 s settle, Follow / Push up, Invert, Amount, MIDI knob learn). `lfoControls` in motion.js now just returns the chip. Buttons (clips, bypass...) are mapped in Map mode (the MIDI button) to MIDI notes/CCs *or* hand gestures: midi.js `onInputEvent(type, ch, n, val)` is the one path for both
  - `safety.js` blackout (`outGain()` multiplies the master in renderComp; Shift+B, BLACK button, MIDI target `blackout`); GPU loss: `webglcontextlost` saves (autosave + sessionStorage active clips / outputs / blackout), sets `window.vjKeepOutputs` so engine.js leaves output windows open, and reloads; on `load` it re-triggers the clips and re-attaches the outputs via `openOutput` (works in the desktop app; a browser's pop-up blocker may refuse). More than 3 losses in a minute stop the reloading. Screen wake lock in the browser; confirm-close while an output is live
  - `clipopts.js` video clip in / out (`c.inP` / `c.outP` fractions), `c.loopMode` loop | hold | eject, `c.syncBeats` beat sync (rate = length / beats at `comp.bpm`, phase from the trigger beat `c.sync0`, drift pulled in by nudging playbackRate, seek only past ~0.25 s). Nudge (2026-11-20): `nudgeSet(src, li, amt, ci)` - every pushing input is a source with a signed amount, summed per layer; the playing clip runs at `c.speed` x (1 + 0.5 x amount) only while pushed (`clipOptsTick(dt)` now sets playbackRate every frame for all active video clips), a beat-synced clip has `c.sync0` moved instead so it stays shifted; `clipSpeedStep` / `clipSpeedReset` are the saved fine trim; `nudgeButton` = hold button (Clip tab, phone clip sheet and Perform layer cards); keys , . (hold, Shift harder), [ ] (trim, Shift 0.1x), \ (1x). Hooks: `clipTriggered` / `clipStart` in engine.js trigger(), `clipOptsJSON` / `clipOptsFrom` / `clipOptsCopy` in save, load and relink. Also the per-clip look, for every clip type (since 2026-11-18): `c.tr` = {s, w, h, x, y, cl, cr, ct, cb} (size, position, crop; absent = untouched) and `c.fx` (the clip's own effect chain, same objects as a layer's). Drawn by engine.js `drawClip` (called instead of `drawSource` by renderComp and applyTransition): crop, then the clip's effects, then size and position, then the layer's scale / position. A video or image without effects stays one pass from its own pixels (`cropProg`); anything else goes through the shared scratch `clipRT`. Saved as `tr` / `fx` on the clip (`clipLookJSON` / `clipLookFrom`); `clipChains()` feeds MIDI `findFx` and shader renames. UI: Clip tab (`clipLookUI` + `chainUI(c.fx)`), drop an effect on a grid cell, double-click an effect while the Clip tab is open; phone: clip sheet (`fxCards`). Snapshots / section looks do not capture clip effects or transforms
  - `looks.js` a look = the visuals' state (`captureLook` / `recallLook` / `lookFromJSON`), glided over `lookGlide.morph` beats by `tickTweens` (audio.js audioTick). Core, so snapshots work without Pro
  - `snapshots.js` 8 slots of looks (looks.js; the glide setting is saved in the snapshots block as `morph`, older files had it in `score`), F1-F8, MIDI `snap:N`, "on next bar". `vjTick(dt)` (safety + clip options + snapshots) runs in ui.js frame() after update()
  - engine.js `videoFrameNew`: a video is re-uploaded only when it has a new frame (requestVideoFrameCallback; when those callbacks go quiet because the control window is not being drawn, a change of currentTime counts instead, or the output would freeze)
  - `audio.js` (core; its decks are only driven by Pro's DJ panel and Agent) DJ audio: two decks on decoded buffers (sample-locked sync; tempo changes pitch, no key lock), the music clock (`musicClock`, which sets `comp.beats` / `comp.bpm` from the audible deck's position while a track plays), live levels in `audioFeat` (shader uniforms `audio.xyzw` = bass, mid, high, level, and `kick`; plus `bar`, `phrase`). The AudioContext is created on first Load/Play, never at page load
  - `motion.js` modulators: `mod[k].src` = kick | bass | mid | high | level (audioFeat) | build | drop (musicFeat) pushes the value up from the slider by `depth`; no `src` = beat LFO; `mix` / `midmix` (musicFeat, written by mix.js) follow an auto-mix's progress. The `mix` look slot (score.js LOOK_SLOTS) is recalled when an auto-mix starts
  - `live.js` listening: microphone / line-in and long music files (played from a `<video>` element, never decoded whole), a live beat tracker (AudioWorklet onset tap from a Blob URL -> autocorrelation + fold every 0.5 s, phase slew, downbeat vote), and the music event bus `onMusic(fn)` / `emitMusic(type, data)`: song, drop, breakdown, band (calm/groove/peak), phrase, tempo, ended. `musicClock` (audio.js) falls back to `liveClock()` when no deck plays. Breakdown = bass gone for 2 bars; drop = the next kick with the bass back; song change = silence gap, lasting tempo change, or harmonic novelty (chroma from a 16k-point analyser), never near a breakdown. Analysed deck sections (score.js) override the live drop/breakdown guesses
  - `panels.js` main-column panels (DJ decks, Agent, More options, Playlist, Composition grid): a slim title bar (click = minimise, ↺ = automatic size; the playlist's minimise button is in its own header) and a drag handle under each. More options is moved out of #agent to be its own panel. A user size is flex `0 0.02 <px>` so other panels give way first; the bottom row keeps `min(240px,34vh)`. Saved in localStorage `strodano-vj-panels`; panelSync follows the DJ / Agent / view toggles through a MutationObserver
  - `display.js` display output (Resolume-style): each screen has `device` = 'auto' (next free display that is not the control display) | 'window' | a display key `label@x,y` (saved in the .svj, matched by key then label). Auto output (on by default, localStorage `strodano-vj-display`): a display that appears (plug-in, or present at start) gets its screens' outputs opened fullscreen on it; an unplugged display closes its output (else the OS would drop a fullscreen output on the control screen). Esc in a placed output = back to a window. Advanced Output shows the Display picker per screen, the display list, Identify (big numbers on each display) and the Auto output switch; the header button reads `Output > Display N`. ## Decisions already made

- Web first, because the owner wants to test without installing/compiling and change code live. FFGL plugins are dropped in the web edition; ISF/GLSL shaders replace them.
- Same workflow and panel arrangement as Resolume (layer/column clip grid, faders, B/S/X, A/B crossfader, BPM tap, effects, advanced output) but its own visual design, not a pixel copy.
- v1 scope: core VJ features + advanced mapping (multiple screens/slices, warping, masks). Since added: media folder, MIDI learn (including effect and generator parameters), keyboard shortcuts, beat LFOs on parameters, beat-timed clip transitions (10 types), music and camera sources for sliders, camera clips and camera input with "(cam)" smart effects, text clips, three.js 3D generators (21), hand tracking and gestures, one input picker for every slider, camera on a layer in one click. Since 2026-11-17 also: display output (Auto / fixed display / window, auto-open on plug-in) and NDI output over the network (desktop). Since 2026-11-18: web link output over the internet (vdo.js, VDO.Ninja SDK vendored: the one outside service the web edition talks to, only when the user starts it). Since 2026-11-18 also: the phone edition (mobile.html PWA) and web link input on the desktop (vdoin.js). Not yet: OSC, body pose / face tracking, NDI input, NDI audio.
- Hard requirement: steady 30 fps or better with H.264 MP4 / .mov clips.
